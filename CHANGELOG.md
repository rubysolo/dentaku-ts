# Changelog

## 0.1.0

Initial release. Dentaku TS is the TypeScript successor to the Ruby
[dentaku](https://github.com/rubysolo/dentaku) gem, by the same author: the
same formula syntax and function catalog, redesigned for TypeScript hosts.

- **Formula language**: arithmetic, comparison, bitwise, and logical
  operators; `CASE ... WHEN ... THEN ... END` (the switch expression needs no
  parentheses); array literals, index/key access, nested data with dotted
  identifiers, backtick-quoted identifiers, Unicode identifiers, C-style
  comments; the full function catalog (logic, numeric, string, collection,
  date, and floating-point math packs).
- **Exact decimal arithmetic** via decimal.js (20 significant digits):
  `0.1 + 0.2 = 0.3` holds, `5 / 2` is exactly `2.5`. Results cross the API
  boundary as `number`/`Date` by default; `{ raw: true }` returns exact
  `Decimal` and civil-date values.
- **Typed errors by default** (ADR-0002): `evaluate`/`solve` throw
  `DentakuError` subclasses (`ParseError`, `UnboundVariableError`,
  `TypeMismatchError`, `ArgumentCountError`, `ZeroDivisionError`,
  `MathDomainError`, `CycleError`); `tryEvaluate` returns `undefined` and
  `trySolve` returns per-key `{ values, errors }` maps — in a dependency
  cycle, only the keys in (or downstream of) the cycle fail while
  independent keys still solve.
- **Per-instance state only**: function registry, AST cache (`astCache`
  option), and memory all live on the `Calculator` — no globals.
- **Five tightenings over the Ruby gem** (ADR-0003/0004), each with its
  restore path documented in the README migration section: case-sensitive
  identifiers (`caseInsensitiveIdentifiers` restores), strict booleans in
  conditionals, no string→number coercion, conventional bitwise precedence,
  and bare date literals off by default (`dateLiterals` restores). Dates are
  constructed explicitly with the new `DATE()` built-in.
- **Measured compatibility**: verified against a 503-entry oracle corpus
  generated by executing Ruby dentaku 3.5.7 over its own spec suite; ~92%
  evaluates identically and all 42 intentional divergences are enumerated in
  `tests/oracle/allowlist.json` with ADR citations. README examples are
  executed in CI (`tests/readme.spec.ts`).
